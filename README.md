## Problem Statement

This project addresses **PS3 — Fund Flow Tracking for Fraud Detection**. Money launderers move criminal proceeds through Union Bank by splitting and routing funds across many accounts, banks, and borders; because each bank sees only isolated transactions, the laundering *network* stays invisible until the money is gone. **G.R.A.P.H AI** (Graph-based Risk Analysis & Pattern Hunting) ingests a live transaction stream, models every account and transfer as a directed temporal multigraph, and runs **five complementary detection engines** over that graph to expose laundering networks — structuring, circular round-tripping, layering chains, fan-in/out, fraud rings, dormant activation, velocity bursts, cross-border layering, and round-tripping — in real time, with a calibrated, explainable risk score per transaction.

## Architecture at a Glance

Three independent systems:

1. **System 1 — Synthetic Ecosystem Generator** *(offline, runs once, then sealed)* — builds 5,000 accounts and ~500K transactions across **10 laundering typologies**; emits a historical set, a stream set, a **sealed** ground-truth file, and a **separate labelled warm-up set** used to train the supervised layer (so the model never sees the evaluation labels).
2. **System 2 — Detection Platform** — offline feature engineering + multigraph construction + model training, then an online per-transaction pipeline (runtime ordering, **5 layers**):
   - **Layer 1 — Rules (D3)** — 15 deterministic FATF-aligned rules (incl. R14 fan-in aggregation, R15 layering-chain relay)
   - **Layer 2 — Graph analytics (D4)** — PageRank, betweenness, fan-in/out, cycles, directed Infomap communities
   - **Layer 3 — Supervised ML (D5)** *(primary)* — XGBoost + LightGBM + Random Forest + SHAP, calibrated
   - **Layer 4 — Behavioural anomaly (D6)** — Isolation Forest + LOF + Autoencoder
   - **Layer 5 — Temporal GNN (D7)** — TGN + MEGA-GNN; node2vec fallback on CPU
   - **D8 fusion** of all five into one calibrated, explained risk score → P2 alerts → Next.js dashboard.
3. **System 3 — Evaluation Engine** *(independent)* — E1–E5 joins alerts against the sealed ground truth and reports minority-class F1, PR-AUC, ROC-AUC, fraud-ring detection rate, per-typology coverage, and per-layer detection credit vs published benchmarks.

A full labelled architecture diagram is in the **D3 — Technical Architecture** document.

## How to Run Locally

**1. Clone the repository**
```bash
git clone https://github.com/emit-humane/GRAPH.AI.git
cd GRAPH.AI
```

**2. Backend — create a virtual environment and install dependencies**
```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

**3. One-shot: run the entire cold pipeline (recommended)**
```bash
bash scripts/run_all.sh
# Generates data → trains every layer → runs full inference → emits evaluation report.
# Add --quick for a small dataset (~5 min), --clean for a true cold start.
```

Or run each stage individually:

**3a. Generate the synthetic dataset (System 1)**
```bash
python -m src.system1_generator
# → data/historical_transactions.csv, data/stream_transactions.csv,
#   data/hidden_ground_truth.csv (sealed), data/warmup_labeled_transactions.csv
```

**3b. Train offline (Shared S1/S2, Layer-2 D4A/D4B, Layer-3 D5A, Layer-4 D6A, Layer-5 D7+D7A)**
```bash
python -m src.system2_detection.shared.s1_feature_engineering
python -m src.system2_detection.shared.s2_multigraph_builder
python -m src.system2_detection.layer2_graph.d4a_graph_preprocessor
python -m src.system2_detection.layer2_graph.d4b_graph_analytics
python -m src.system2_detection.layer3_supervised.d5a_training
python -m src.system2_detection.layer4_anomaly.d6a_training
python -m src.system2_detection.layer5_gnn.d7_node2vec
python -m src.system2_detection.layer5_gnn.d7a_tgn_training
```

**3c. Online inference sweep (D1 → D2 → D3 → D4 → D5 → D6 → D7 → D8 → P2)**
```bash
python scripts/run_pipeline_full.py --clear-alerts --strict-layers
# → data/generated_alerts.csv, logs/alerts.db
```

**4. Start the live detection API**
```bash
make backend           # uvicorn src.api.main:app on :8000
```

**5. Start the dashboard**
```bash
make install-frontend  # one-time
make frontend          # Next.js on :3000 — open http://localhost:3000
```

**6. (Optional) Run the evaluation engine (System 3)**
```bash
python scripts/run_evaluation.py
# → reports/evaluation_report.json + transaction/community/pattern metrics
```

## Dataset

All data is **100% synthetic**, generated by `src/system1_generator`. It simulates:

- **5,000 accounts** with realistic KYC levels, banks, countries, and shell-entity flags
- **~500,000 transactions** across a 90-day historical window, whose amounts follow **Benford's law**
- **10 laundering typologies**: structuring, circular laundering, layering chains, fan-in, fan-out, fraud rings, dormant-account activation, velocity bursts, cross-border layering, round-tripping
- A realistic ~0.8% illicit base rate (configurable), with full ground-truth labels in `hidden_ground_truth.csv` *(sealed; only System 3 reads it)*
- A separate **warm-up labelled set** generated with `seed+1000` for supervised training — guarantees the supervised layer never sees the evaluation labels

To regenerate: run step 3a above. The generator is seeded (`seed: 42` in `config.json`) and fully reproducible. **No real bank data is used.** Calibration parameters are drawn from published research (IBM AMLworld, Altman et al. NeurIPS 2023; LaundroGraph, Cardoso et al. ICAIF 2022; Benford-law subgraph work).

## Known Limitations

- Trained and evaluated on **synthetic data only**; real deployment needs retraining and recalibration on actual bank transaction streams.
- The **TGN's TP-leader credit is 0 %** because Layer 5 mostly contributes risk *signal* rather than the dominant fusion contribution under the spec weights (0.10). Further calibration + longer training (the demo runs 1 smoke epoch) is needed to push TGN above the supervised model on relay-style typologies.
- **Cross-border-layering, fan-out, and velocity-burst** detection rates are 0 % in this run — the synthetic generator emits very few exemplars in these typologies at the 0.8 % illicit ratio, so the supervised model under-learns them. Up-sampling and class-weighting on these typologies is the next iteration's work.
- Processes a **replayed CSV stream**; production would ingest from Kafka or the bank's real-time rails.
- The full **Temporal Graph Network (Layer 5)** benefits from GPU training; a **node2vec fallback** runs on CPU where GPU is unavailable.
- **Not connected** to live banking systems or FIU-IND; STR-style output simulates the reporting format and is not a legally-filed report.
- **No authentication** on the dashboard — acceptable for a POC demo, not for production.
- The `latency_metrics` block in `evaluation_report.json` mixes synthetic stream timestamps (2025) with wall-clock alert timestamps (2026); the headline latency above is the **real per-event scoring cost** measured during inference (≈ 78 ms), not the JSON's misleading delta.
