## Problem Statement

This project addresses **PS3 — Fund Flow Tracking for Fraud Detection**. Money launderers move criminal proceeds through Union Bank by splitting and routing funds across many accounts, banks, and borders; because each bank sees only isolated transactions, the laundering *network* stays invisible until the money is gone. **GraphSentinel** ingests a live transaction stream, models every account and transfer as a directed temporal multigraph, and runs five complementary detection engines over that graph to expose laundering networks — structuring, circular round-tripping, layering chains, fan-in/out, fraud rings and more — in real time, with a calibrated, explainable risk score per transaction.

## Architecture at a Glance

Three independent systems:

1. **System 1 — Synthetic Ecosystem Generator** *(offline, runs once, then sealed)* — builds 5,000 accounts and 500K transactions across 10 laundering typologies; emits a historical set, a stream set, a **sealed** ground-truth file, and a **separate labelled warm-up set** used to train the supervised layer (so the model never sees the evaluation labels).
2. **System 2 — Detection Platform** — offline feature engineering + multigraph construction + model training, then an online per-transaction pipeline:
   - **Layer 1 — Rules** (15 deterministic FATF-aligned rules)
   - **Layer 2 — Graph analytics** (PageRank, betweenness, fan-in/out, cycles, directed Infomap communities)
   - **Layer 3 — Supervised ML** *(primary)* (XGBoost + LightGBM + Random Forest + SHAP)
   - **Layer 4 — Behavioural anomaly** (Isolation Forest + LOF + Autoencoder)
   - **Layer 5 — Temporal GNN** (TGN + MEGA-GNN; node2vec fallback on CPU)
   - **Fusion** of all five into one calibrated, explained risk score → alerts → Next.js dashboard.
3. **System 3 — Evaluation Engine** *(independent)* — joins alerts against the sealed ground truth and reports minority-class F1, PR-AUC, ROC-AUC, fraud-ring detection rate, and per-typology coverage vs published benchmarks.

A full labelled architecture diagram is in the **D3 — Technical Architecture** document.

## How to Run Locally

> Update module/script names to match your repo if they differ.

**1. Clone the repository**
```bash
git clone https://github.com/<your-team>/graphsentinel.git
cd graphsentinel
```

**2. Backend — create a virtual environment and install dependencies**
```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

**3. Generate the synthetic dataset (System 1)**
```bash
python -m system1_generator.run
# → produces historical_transactions.csv, stream_transactions.csv,
#   hidden_ground_truth.csv (sealed), warmup_labeled_transactions.csv
```

**4. Run the offline pipeline (System 2 — features, graph, model training)**
```bash
python -m system2_platform.offline.run
# → behavioural_features, transaction_multigraph, graph_features,
#   trained models (xgb/lgbm/rf + SHAP, isolation_forest, lof, autoencoder, tgn/node2vec)
```

**5. Start the online detection API (System 2 — online)**
```bash
uvicorn system2_platform.online.app:app --reload --port 8000
```

**6. Start the frontend dashboard**
```bash
cd frontend
npm install
npm run dev
# open http://localhost:3000
```

**7. (Optional) Run the evaluation engine (System 3)**
```bash
python -m system3_evaluation.run
# → evaluation_report.json + PR/ROC curves
```

## Dataset

All data is **100% synthetic**, generated by `system1_generator`. It simulates:
- 5,000 accounts with realistic KYC levels, banks, countries, and shell-entity flags
- ~500,000 transactions whose amounts follow **Benford's law**
- **10 laundering typologies**: structuring, circular laundering, layering chains, fan-in, fan-out, fraud rings, dormant-account activation, velocity bursts, cross-border layering, round-tripping
- A realistic ~0.8% illicit base rate, with full ground-truth labels

To regenerate: run step 3 above. The generator is seeded (`seed: 42`) and fully reproducible. **No real bank data is used.** Calibration parameters are drawn from published research (IBM AMLworld; Benford-law subgraph work).

## Known Limitations

- Trained and evaluated on **synthetic data**; real deployment needs retraining and recalibration.
- Processes a **replayed CSV stream**; production would ingest from Kafka or the bank's real-time rails.
- The full **Temporal Graph Network (Layer 5)** benefits from GPU training; a **node2vec fallback** runs on CPU where GPU is unavailable.
- **Not connected** to live banking systems or FIU-IND; STR-style output simulates the reporting format and is not a legally-filed report.
- No authentication on the dashboard (acceptable for a POC demo, not for production).
